# Kafka Topics

## Overview

Apache Kafka is the event streaming backbone of the Fabiq Smart Factory MES Integration Platform. Rather than communicating directly, services exchange manufacturing events through Kafka topics, enabling loose coupling, scalability, and independent service evolution.

---

# Event-Driven Architecture

```text
Machine Simulator
        │
        ▼
     Apache Kafka
   ┌────┴───────────┐
   ▼                ▼
Backend API   AI Anomaly Worker
   │                │
   └──────┬─────────┘
          ▼
     React Dashboard
```

---

# Core Topics

| Topic | Producer | Consumer | Purpose |
|------|----------|----------|---------|
| `machine.status` | Simulator | Backend API | Machine state changes |
| `production.counts` | Simulator | Backend API | Production output |
| `downtime.events` | Simulator | Backend API | Downtime tracking |
| `machine.telemetry` | Simulator | AI Worker | Equipment telemetry |
| `maintenance.alerts` | AI Worker | Backend API | Maintenance notifications |

---

# Topic Details

## machine.status

Tracks the current operating state of each machine.

Typical fields:

- machineId
- lineId
- status
- timestamp
- workOrderId

---

## production.counts

Captures production activity.

Typical fields:

- workOrderId
- quantity
- goodCount
- scrapCount
- partId
- timestamp

---

## downtime.events

Records planned and unplanned downtime.

Typical fields:

- machineId
- reasonCode
- startTime
- endTime
- duration

---

## machine.telemetry

Provides equipment telemetry consumed by the AI anomaly worker.

Typical fields:

- temperature
- vibration
- cycleTime
- errorCount
- scrapRate
- timestamp

---

## maintenance.alerts

Generated by the AI anomaly worker after evaluating telemetry.

Typical fields:

- machineId
- severity
- alertType
- message
- timestamp

# Topic Initialization

During Docker Compose startup, the `kafka-init` service creates the required topics automatically. This ensures Kafka UI displays the expected topics before new events are published.

# Best Practices

- Keep event payloads immutable.
- Use domain-specific topics.
- Avoid direct service-to-service messaging for manufacturing events.
- Validate event payloads before persistence.
- Add schema validation (for example, Schema Registry) in future versions.
